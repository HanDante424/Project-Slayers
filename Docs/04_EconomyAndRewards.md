# Project Slayers - Economy and Rewards

상태: 현재 활성 경제·보상 기획 기준  
용도: 스테이지 보상, 장비 제작·강화, 분해, 옵션, 희귀 재료, 천장 구조의 구현 방향 관리

---

## 1. 보상 기본 원칙

일반적인 바닥 드롭/줍기 구조를 핵심 보상 방식으로 사용하지 않는다.

스테이지 종료 후:

1. 스테이지 결과 계산
2. 보상 배율 적용
3. 최종 보상 계산
4. 인벤토리에 자동 지급

핵심 설계에서 제외되는 것:

- 바닥 아이템 GameObject
- 드롭 위치
- 플레이어가 직접 줍지 않은 드롭의 저장
- 바닥 드롭 오브젝트 풀링

특정 연출용 드롭이 필요할 수는 있으나,
게임의 핵심 보상 데이터 구조를 바닥 오브젝트에 의존시키지 않는다.

---

## 2. 무한 난이도

동일 콘텐츠에 무한적으로 상승 가능한 난이도 구조를 둔다.

목표:

- 동일 콘텐츠의 장기 반복 가능성
- 성장한 캐릭터가 더 높은 난이도에 도전
- 보상과 난이도의 장기 확장

세부 난이도 공식과 보상 배율 공식은 현재 미확정이면 임의 생성하지 않는다.

---

## 3. 아이템 분해

획득 아이템은 분해해 재화화할 수 있다.

목표:

- 필요 없는 장비/아이템의 가치 보존
- 장기 성장 재화로 환원
- 반복 획득 아이템의 활용

주의:

쉬운 스테이지 반복 → 대량 분해 → 범용 재화 무한 축적이 최적해가 되어
경제가 붕괴하지 않도록 설계해야 한다.

구체 분해량 공식은 미확정이면 임의 생성하지 않는다.

---

## 4. 장비 제작

장비는 제작형으로 운용한다.

원칙:

- 원하는 장비의 최초 획득은 과도하게 어렵지 않게 한다.
- 초기 제작 비용은 낮게 둔다.
- 제작 불가 희귀 재료를 사용할 수 있다.
- 그러나 극저확률 물욕템 반복을 핵심 성장 구조로 강제하지 않는다.

---

## 5. 장비 강화

강화에는 해당 장비 제작에 사용되는 아이템/재료를 다시 소비한다.

목표:

- 이미 확보한 제작 재료의 지속적인 소비처 제공
- 장비 획득 이후에도 동일 콘텐츠 보상의 가치 유지

강화 단계, 성공률, 파괴 여부, 비용 상승식은 현재 확정된 자료가 없으면 임의로 만들지 않는다.

---

## 6. 세트 옵션

특정 고정 장비에만 세트 옵션을 묶지 않는다.

소비를 통해 원하는 세트 옵션을 장비에 부여할 수 있게 한다.

목표:

- 장비 외형/기본 성능과 세트 빌드의 결합 자유도 확보
- 특정 장비 드롭에 대한 과도한 종속 완화

세트 옵션 부여 재료와 비용은 별도 확정이 필요하다.

---

## 7. 장비 옵션

장비 옵션 수치는 랜덤이다.

아이템 소비를 통해 리롤할 수 있다.

구현 시 분리해야 할 개념 예:

- 장비 기본 정의
- 장비 인스턴스
- 옵션 목록
- 옵션 수치
- 세트 옵션
- 강화 상태

ScriptableObject 정의 에셋 자체를 개별 장비 인스턴스로 사용하지 않는다.

---

## 8. 희귀 재료

제작 불가 희귀 재료를 사용할 수 있다.

단:

- 극저확률 단일 드롭을 강제로 수백/수천 회 반복하는 구조는 지양
- 희귀 파밍 피로 완화 장치를 둔다.

대표 완화 장치:

- 천장 게이지

---

## 9. 천장 게이지

천장 게이지 채용은 확정 방향이다.

현재 미확정:

- 최대 게이지
- 1회 증가량
- 난이도 보정
- 직접 드롭률
- 획득 후 초기화 여부
- 스테이지별 분리 여부
- 보상 자동 지급 여부
- 보상 선택 방식 여부

따라서 Codex는 천장 구조를 구현할 때
임의의 숫자를 확정값으로 넣지 않는다.

필요하다면:

- 인터페이스
- 데이터 필드
- 저장 구조
- 확장 가능한 게이지 계산 지점

정도까지만 수치 비종속적으로 설계할 수 있다.

---

## 10. 경제 붕괴 방지 원칙

피해야 할 대표적 최적해:

`쉬운 스테이지 반복 → 대량 아이템 획득 → 대량 분해 → 범용 재화 과잉 → 상위 콘텐츠 무의미`

따라서 향후 경제 설계에서는 다음을 함께 고려한다.

- 난이도별 보상 구조
- 재화 종류의 역할 분리
- 분해 가치
- 제작/강화 소비량
- 희귀 재료의 공급
- 무한 난이도 보정
- 리롤 소비
- 세트 옵션 부여 비용

단, 구체 수치는 사용자 확정 전까지 미정이다.

---

## 11. 스테이지 클리어 보상 데이터의 목표

권장 개념:

- 기본 보상
- 난이도 배율
- 추가 조건 배율
- 최종 지급량
- 지급 대상 아이템/재화
- 천장 진행도
- 첫 클리어 여부
- 반복 클리어 여부

구체 클래스 구조는 현재 코드와 함께 결정한다.

---

## 12. 저장과 보상

스테이지 보상은 자동 지급되므로
클리어 결과와 저장 처리의 순서가 중요하다.

향후 저장 안정화에서 고려할 항목:

- 보상 계산 완료
- 인벤토리 반영
- 천장 게이지 반영
- 저장 성공
- 씬 이동

저장 실패 시 보상 중복 지급/소실이 발생하지 않도록
트랜잭션 또는 안전한 저장 순서를 설계해야 한다.

현재 정확한 실패 복구 정책은 미확정이다.

---

## 13. 현재 테스트 전투와의 관계

[ACTIVE UPDATE 2026-10-31]

과거의 "테스트 스킬 3회 사용 → 재화 100 지급 → 저장 → Town 이동" 흐름은 현재 코드에 없다.

현재 코드의 재화·보상 관련 상태:

- 재화는 `SharedInventory`의 골드와 기억의 파편이다.
- 개발용 상점(`TownDevShopController`)이 아이템과 재화 팩(10,000 단위)을 무료 지급한다. 개발 전용이며 정식 가격이 아니다.
- `MapData`에 골드·기억의 파편 보상 값이 정의되어 있으나, 전투 종료 시 실제로 지급하는 경로는 아직 없다.
- `GameData.testCurrency`와 `TownTestMenu`의 ±10 테스트 재화는 레거시 테스트 코드로 남아 있다.

테스트 코드나 개발 상점에 존재하는 수치를 정식 경제 수치로 승격하지 않는다.

---

## 14. 구현 시 금지

다음은 명시적 결정 없이 Codex가 확정하지 않는다.

- 드롭률
- 천장 최대값
- 천장 증가량
- 난이도 보정식
- 제작 비용
- 강화 비용
- 강화 성공률
- 옵션 리롤 비용
- 옵션 등급별 확률
- 분해 가치
- 세트 옵션 비용
- 희귀 재료 요구량
- 무한 난이도 보상 배율

필요한 경우 후보안을 제안할 수 있으나
반드시 "제안"으로 표시하고 캐논/확정값으로 취급하지 않는다.
