# Project Slayers - Action System

상태: 현재 활성 구현 기준  
용도: 플레이어/전투 행동, 이동 권한, 캔슬, 강제 중단, 종료 및 정리 구조 정의

> 구현 현황 (2026-10-31): 이 문서는 목표 구조다. 현재 코드에는 공통 `ActionController`,
> 행동 단계(`Startup`~`Finished`), `CancelPower` / `InterruptArmor`가 아직 없다.
> 이동 권한(`CharacterMotor2D.MovementControl`)과 액션별 입력 버퍼(`ActionInputBuffer`)는 존재하며,
> 메이헴 액션은 `MayhemMechanism`이 캐릭터 단위로 직접 관리한다.

---

## 1. 기본 원칙

행동의 권위(authority)는 Animator가 아니라 게임플레이 코드에 있다.

권장 중심 객체:

- `ActionController`
- 또는 동일한 책임을 가지는 게임플레이 컨트롤러

Animator는 행동 결과를 표현한다.

---

## 2. 행동 단계

일반 행동은 필요한 경우 다음 단계를 사용한다.

1. `Startup`
2. `Active`
3. `EarlyRecovery`
4. `LateRecovery`
5. `Finished`

의미:

### Startup
행동 시작 준비 구간.

예:
- 선딜레이
- 자세 잡기
- 히트박스가 아직 활성화되지 않은 구간

### Active
행동이 실제 효력을 가지는 핵심 구간.

예:
- 공격 히트박스 활성
- 투사체 생성
- 이동 공격의 실제 공격 판정

### EarlyRecovery
행동 후반의 비교적 강한 후딜레이 구간.

- 일부 연계만 허용될 수 있다.
- 정확한 허용 행동은 액션 데이터/설계에 따른다.

### LateRecovery
행동 종료 직전의 완화된 후딜레이 구간.

- 더 많은 행동이 허용될 수 있다.
- 정확한 허용 관계는 별도 설계가 필요하다.

### Finished
행동 종료 상태.

---

## 3. 단계 시간

각 단계의 실제 시간은 행동별 데이터다.

현재 공통 수치로 확정하지 않는다.

미확정:

- Startup 기본 시간
- Active 기본 시간
- EarlyRecovery 기본 시간
- LateRecovery 기본 시간
- 단계 전환의 프레임 기준
- 애니메이션 길이와 행동 시간의 정확한 관계

Codex가 임의의 기본 시간을 만들지 않는다.

---

## 4. 이동 권한

행동 중 이동 권한은 다음 세 가지를 기준으로 한다.

- `Locked`
- `Reduced`
- `Free`

### Locked
일반 이동 입력이 캐릭터 이동을 제어하지 못한다.

주의:

- `Locked`가 Rigidbody 속도를 무조건 0으로 만든다는 뜻은 아니다.
- 공격 자체의 강제 이동, 넉백, 외력, 연출 이동은 별도 제어할 수 있다.

### Reduced
행동별 제한 아래 이동이 가능하다.

예:
- 이동 속도 배율 제한
- 방향 전환 제한
- 일부 입력만 허용

정확한 제한 수치는 행동 데이터에서 정의한다.

### Free
일반 이동 입력이 정상적으로 허용된다.

---

## 5. 일반 연계

일반 연계는 현재 액션의 캔슬 윈도우가 요청된 다음 행동을 허용하는지 검사한다.

기본 개념:

- 현재 액션
- 현재 단계 / 캔슬 윈도우
- 요청된 다음 행동
- 허용 행동 태그

현재 구조 목표:

`현재 캔슬 윈도우 → 허용 행동 태그 검사 → 다음 행동 허용/거부`

행동마다 별도 bool을 추가하는 구조를 기본으로 사용하지 않는다.

---

## 6. 강제 캔슬

강제 캔슬은 다음 두 개념을 비교한다.

- 새 행동 또는 제어 효과의 `CancelPower`
- 현재 행동 구간의 `InterruptArmor`

기본 구조:

`CancelPower`가 현재 구간의 `InterruptArmor`를 이길 수 있는지 판정하여 강제 중단 여부를 결정한다.

현재 미확정:

- 실제 수치 범위
- 동률 처리
- 상태별 예외
- 특정 보스/플레이어 특수 규칙

임의 수치를 만들지 않는다.

---

## 7. 상위 제어 상태

일반 행동 흐름보다 우선할 수 있는 상위 제어 상태:

- `HitStun`
- `KnockDown`
- `Grabbed`
- `Dead`
- `Cutscene`

이 상태들은 일반 스킬 연계와 별도로 관리할 수 있다.

정확한 우선순위와 상호 전환은 구현 시 명시적으로 정의한다.

---

## 8. 행동 종료 경로

모든 행동은 정상 종료와 강제 종료를 명확히 구분한다.

정상 종료:

- `CompleteAction`

취소 / 강제 중단:

- `CancelAction`

두 경로 모두 공통 정리 단계로 이어져야 한다.

---

## 9. Cleanup

`CompleteAction`과 `CancelAction`은 공통 Cleanup을 호출한다.

Cleanup 대상 예:

- 공격 Hitbox
- 임시 Collider
- 이동 잠금
- 이동 속도 제한
- 강제 이동 상태
- Coroutine
- Timer
- Trail
- Particle
- 임시 VFX
- 적중 대상 목록
- 다단 히트 대상 기록
- Target 참조
- 이벤트 구독
- 임시 스탯 Modifier
- 임시 입력 제한
- 액션이 생성한 풀 오브젝트
- 액션 전용 임시 플래그

규칙:

- 정상 애니메이션 마지막 프레임에 도달해야만 정리되는 구조를 만들지 않는다.
- 강제 취소되어도 액션이 남긴 상태가 누수되지 않아야 한다.

---

## 10. Animator와의 관계

Animator는 결과 출력 계층이다.

금지되는 기본 패턴:

- Animator state name으로 "현재 공격 중" 판정
- Animator state name으로 이동 잠금 판정
- Animator state name으로 캔슬 가능 여부 판정
- 애니메이션 종료 여부만으로 액션 종료 처리
- Animator가 게임 상태 전환을 단독 결정

허용 가능한 사용:

- 게임플레이 상태를 Animator parameter로 전달
- 명시적으로 설계된 Animation Event
- 타격 프레임에 맞춘 이벤트 전달

단, Animation Event가 누락되거나 액션이 취소되어도 Cleanup은 보장되어야 한다.

---

## 11. 입력 버퍼

입력 버퍼는 향후 구현 대상이다.

목표:

- 허용 시점보다 약간 먼저 입력된 명령 보존
- 캔슬 윈도우가 열리면 버퍼 입력 평가
- 행동 종류별 허용 관계와 연동

현재 미확정:

- 기본 버퍼 시간
- 입력별 버퍼 시간 차이
- 여러 입력이 들어왔을 때 우선순위
- 동일 입력 중복 처리
- 버퍼 제거 시점

---

## 12. 행동 데이터 구조의 목표

행동마다 다음과 같은 정보를 데이터화할 수 있어야 한다.

예시 개념:

- Action ID 또는 명시적 타입
- 행동 태그
- 각 단계 시간
- 단계별 이동 권한
- 단계별 InterruptArmor
- 캔슬 윈도우
- 허용 다음 행동 태그
- CancelPower
- 행동 종료 규칙

구체 클래스/ScriptableObject 구조는 구현 단계에서 현재 코드와 함께 결정한다.

숫자 ID 하나와 대형 switch로 모든 행동을 처리하는 구조는 피한다.
