# Project Slayers - Mayhem Carnival System

상태: 현재 활성 플레이어 캐릭터 기준  
용도: 메이헴 카니발의 기본 자원, 패시브, 스킬 동작, 단계 및 구현 시 확정사항 관리

---

## 1. 캐릭터 기본

이름:

- 메이헴 카니발
- Mayhem Carnival

전투 성향:

- 피를 사용하는 버서커형 전투광
- 기술은 기본적으로 물리 기반
- 기본 공격 속성은 물리 속성
- 주요 자원은 체력
- 베르세르크 공통 기관인 `피의 샘`을 사용

---

## 2. 피의 샘

피의 샘은 베르세르크 공통 자원 기관이다.

기능:

- 혈액을 압축 저장
- 기술 사용 시 방출
- 메이헴은 피를 무기 형태로 생성해서 사용

자원 규칙:

- 스킬별 피의 샘 소모는 고정 수치가 아니라 최대치 비례 백분율
- 실제 스킬별 소모 비율은 아직 확정하지 않은 항목이 존재함

임의 수치를 만들지 않는다.

## 4. 혈류 조작

핵심 패시브.

확정 효과:

- 모든 출혈을 과다출혈로 변환
- 과다출혈은 출혈로도 취급
- 모든 피해를 출혈로 변환
- 변환 계수는 혈류 조작의 계수를 사용
- 출혈은 무속 물리 피해
- 과다출혈은 고정 피해
- 잃은 체력에 비례해 공격속도와 이동속도 증가

구현 시 주의:

- 출혈과 과다출혈은 동일 상태가 아니다.
- 과다출혈은 출혈 판정을 공유하지만 별도 효과를 가진다.
- 모든 피해 → 출혈 변환의 정확한 처리 순서는 피해 시스템과 연동하여 구현한다.
- 고정 피해의 세부 처리 규칙은 아직 피해 문서에서 미확정이므로 임의로 완성하지 않는다.

## 5. 블러드 소드

기본:

- 피의 검 사용

동작:

1. 1타: 수직 베기
   - Y축 범위가 넓은 공격
2. 2타: 수평 베기
   - X축 범위가 넓은 공격

강화:

- 공격 범위 증가
- 피해 증가

폐기:

- 체력 회복 효과는 사용하지 않는다.

[ACTIVE UPDATE 2026-10-31] 사용자 확정:

- 블러드 소드는 3타 공격이다. 현재 코드의 `BloodSword00` / `01` / `02` 3타 콤보를 기준으로 한다.
- 위 동작 목록의 1타·2타 설명은 유지한다.
- [CHECK] 3타의 동작 설명(베기 방향·범위 특성)은 아직 문서화되지 않았다. 사용자 결정 필요.

- 디버프

## 9. 블러드 램페이지

확정:

- 추가 공격은 확정 크리티컬

정확한 추가 공격 구조/계수는 관련 세부 스킬 데이터가 필요하다.

---

## 10. 블러드 디스트럭션

현재 단계 및 선행 조건은 확정되어 있으나,
세부 동작/피해 수치는 별도 최신 스킬 원본이 필요한 경우 해당 자료를 우선한다.

Codex가 이름만으로 동작을 추정하지 않는다.

---

## 11. 블러드 클로

확정:

- 체력 회복량 성장 범위는 `10 → 30`
- 과거 `5 → 15`는 폐기

세부 동작/계수는 최신 스킬 원본이 필요한 경우 관련 자료를 먼저 확인한다.

---

## 12. 블러드 버스터

확정:

- 2단계 스킬
- 추가 공격에 무력화 증가 효과 적용

세부 피해/타격 구조는 최신 스킬 원본을 우선한다.

---

## 13. 넘치는 피의 축제

확정 변경:

- 적 처치 시 체력 회복 효과 폐기
- 대상의 과다출혈 중첩이 최대치에 도달하면:
  1. 대상의 모든 과다출혈 중첩 소모
  2. 메이헴 체력 회복

과다출혈 최대 중첩 수와 정확한 회복 공식은 별도 확정이 필요하면 임의 생성하지 않는다.

---

## 14. 블러드 체인쏘

현재 3단계 스킬.

확정:

- 추가 공격은 사방의 전기톱이 중앙으로 수렴하는 형태
- 확정 크리티컬
- 크리티컬 피해량 증가

정확한 수치와 프레임은 미확정이면 임의 생성하지 않는다.

## 22. 구현 시 금지

Codex는 다음을 임의로 만들지 않는다.

- 피해 계수
- 체력 비용
- 피의 샘 비용
- 쿨타임
- 타격 수
- 프레임
- 이동 거리
- 히트박스 크기
- VFX 크기
- 과다출혈 최대 중첩
- 체력 회복 공식
- 확정되지 않은 디버프 수치
- 확정되지 않은 스킬 동작

필요한 값이 없으면 사용자 결정이 필요한 항목으로 보고한다.
